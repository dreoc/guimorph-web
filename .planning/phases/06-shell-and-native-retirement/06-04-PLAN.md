Strip the Tk chrome and native-engine call sites from `R/3dDigitize.main.r` (~3,586 lines,

(Plans 01/02) is the replacement control surface.

Purpose: UI-01 (Tk control surface gone from the main file) + UI-02 (no engine verbs left).
Output: a stripped `3dDigitize.main.r` and a source-scan guard test.
</objective>

## Wave 3 parallel-execution contract (Plans 06-04, 06-05, 06-06)

The three demolition plans run in parallel and must never double-edit the same line.
`files_modified` are **disjoint by design** — each plan owns a fixed, non-overlapping set:

| Plan | Owns (exclusive) |
|------|------------------|
| 06-04 (this plan) | `3dDigitize.main.r` — incl. the S3 **generic definitions** `ui`/`init`/`bind`/`updateWidgets` (~75–89) AND any `*.main` methods that live in `main.r` |
| 06-05 | `3dDigitize.digitize.r`, `3dDigitize.curve.r` — incl. any `*.main`/tab S3 methods defined **in those files** |
| 06-06 | `3dDigitize.surface.r`, `3dDigitize.geomorph.r`, `transport.R` — incl. any `*.main`/tab S3 methods defined **in those files** |

**S3 rule (removes the cross-file audit race):** Each plan deletes only the S3 methods that
physically live in its own files. This plan owns the four **generic definitions** in `main.r`.
Removing a generic while a sibling method is momentarily still present (or vice-versa, across
parallel worktrees) is **safe and order-independent**, because Plan 06-03 already removed the
`ui(e)`/`init(e)` `UseMethod` dispatch from the entry — any transiently-orphaned method is an
inert plain function that nothing dispatches to. Do **not** read/mutate sibling files here.

**Shared touchpoints:** none in Wave 3. `NAMESPACE` regeneration (which would otherwise be a
shared write) is deferred entirely to Plan 06-08 (Wave 5); no Wave-3 plan edits `NAMESPACE`.
`transport.R` is edited only by Plan 06-06 in this wave (its Wave-1 edit in 06-01 is a prior wave).
