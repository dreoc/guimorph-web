Grow the browser page (`GMW_VIEW3D_TEMPLATE` in `view3d.R`) from the Phase-5 HUD + mode
toolbar into a full shell at Tk parity: a DOM tab strip (digitize / anchor / surface /
curve / GPA), a menu bar (File: Load PLY/DGT, Add PLY, Save, Export, Merge; Help), a status

picker, the message box, the color picker, and the save-name field. This is the client half
of UI-01; it consumes the routes built in Plan 01.

and Merge reuse the same picker modal with a checkbox multi-select list plus a save-name text
field posting to `/savepath` (Plan 06-01), rather than a native `multiple = TRUE` chooser. This
is settled in Task 2 and is no longer an open question.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser DOM → `httpuv` routes | The picker UI submits a file selection; the server-side guard (Plan 01) is authoritative — the client never joins paths |
| browser → LAN | Page fetches are relative same-origin only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-6-06 | Tampering | file-picker client trusting its own path | high | mitigate | Client sends only a basename chosen from the R-enumerated `/files` list; membership + traversal enforcement stays server-side (Plan 01 T-6-02) — the client adds no path logic |
| T-6-07 | Information disclosure | absolute/CDN fetch leaking off-loopback | high | mitigate | All fetches use relative same-origin route names (no absolute URLs, no CDN, no runtime network) per REFERENCE-ARCHITECTURE |
| T-6-08 | Tampering | color/save-name body injection | low | accept | Values are stored and validated server-side (Plan 01 `/color` hex check, `/savepath` name); client passes them through unmodified |
