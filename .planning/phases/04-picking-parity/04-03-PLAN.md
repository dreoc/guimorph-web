<objective>
Build the R side of the PICK-03 parity gate: the mean-inter-vertex-edge-length tolerance
calculation, the distance / 95th-percentile comparison, the base-R fixture reader, a
schema-true placeholder pose-record fixture, and the skip-safe harness test. Because native
capture is Windows-only and no host is available (D-06), PICK-03 is built end-to-end against
the placeholder and left **formally OPEN**; the identical harness closes the gate with zero
code change when the real Windows capture is dropped in (D-07).

**Tolerance for user approval (D-01/D-02/D-03).** The gate is scale-relative:
`p95(browser-vs-native Euclidean distance) <= 1 x mean inter-vertex edge length`. For
`B7_1_clean.ply` RESEARCH computed the mean inter-vertex edge length at **≈ 0.0850 model
units** (median 0.0836, p95 0.1096), i.e. the gate lands one mesh cell (~0.14% of the bbox
diagonal). If the model units are millimetres (NextEngine convention, A1), that is
**~12–35× tighter** than the 1–3 mm inter-observer digitizing error established in the
literature (Fruciano/Barbeito-Andrés 2018; Maudgil; Chollet — RESEARCH D-03 citations). The
scale-relative claim holds regardless of the unit assumption. **This final number requires
user approval at plan time.**

Purpose: R owns the fixture, the tolerance unit, and the pass/fail gate; the browser only
produces the replayed hit (Plan 02). Output: `R/parity.R`, the placeholder TSV, and
`test-picking-parity.R`.
</objective>

    printer (never raw `print`); base R + `stats`/`utils` only — NO `jsonlite` (view3d.R
    no-JSON policy). Take the math verbatim from RESEARCH "Code Examples":

    `.gmw_mean_edge_length(m)` — from an Rvcg mesh, `V <- t(m$vb[1:3, , drop = FALSE])`,
    `it <- t(m$it)` (F×3, 1-based), stack the three edges per face
    (`rbind(it[,c(1,2)], it[,c(2,3)], it[,c(3,1)])`), compute per-edge Euclidean distance and
    return `mean(d)`. This is the D-01 tolerance unit (≈ 0.085 for B7_1_clean.ply).

    `.gmw_parity_gate(browser_xyz, native_xyz, mean_edge)` — coerce both inputs to numeric
    matrices with 3 columns, compute per-row Euclidean distance
    `d <- sqrt(rowSums((browser_xyz - native_xyz)^2))`, and return
    `list(p95 = stats::quantile(d, 0.95, names = FALSE), pass = stats::quantile(d, 0.95,
    names = FALSE) <= 1 * mean_edge, n = length(d))`. The gate is the 95th percentile, not
    the max (D-02), which tolerates the depth-interpolation residual tail (D-09).

    `.gmw_read_pick_poses(path)` — `utils::read.table(path, header = TRUE, sep = "\t",
    comment.char = "#", stringsAsFactors = FALSE)`; the `#` header comment line (specimen +
    sha256 + engine_commit + captured) is skipped by `comment.char`. Return the data frame
    with the fixed column set from the Pose-Record Schema.
  </action>
