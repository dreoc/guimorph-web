<objective>
Add the browser interaction and overlay rendering for the full acquisition workflow to
the `view3d.R` template: anchor placement, curve definition by landmark index with the
cyan/red/blue feedback, surface semilandmark point-cloud display, and delete/undo/
specimen-switch controls. R already owns the state and the routes (05-02); this plan is
the pure view/input layer over them. It edits `view3d.R` once so no other Wave-2 plan
touches it.

Purpose: DGT-01 (curves + anchors) and DGT-02 (surface display/delete/undo/multi-specimen)
are browser interactions posting bare-CSV bodies over the Phase-4 route pattern.
Anchors reuse the exact pick shape with a distinct color and a SECOND overlay group so
anchor dots are never re-hit by `intersectObject(pickMesh, false)` (RESEARCH Pattern 3).
Curves are landmark INDICES (RESEARCH Pattern 2). Surface points arrive pre-flattened
from R via `.gmw_flat` (the mandatory transpose lives R-side, 05-04).
Output: the interactive digitizing template + a source-scan test of the wiring.

Consumes the 05-02 route contract: sendBeacon targets `anchor`, `curve`, `delete`,
`undo`, `specimen` (relative same-origin, mirroring the existing `pick`/`close` beacons).
Multi-specimen uses the A4 RE-SERVE design: `/specimen` returns the next mesh URL +
overlays; the browser loads it and rebuilds the BVH (Pitfall 4).
</objective>
