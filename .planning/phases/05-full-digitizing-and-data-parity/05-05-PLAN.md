<objective>
Drive GPA (`geomorph::gpagen`) and `.csv`/`.rds` export from the browser, producing output
identical to the native path by construction. The GPA, PCA, mean-shape, and export
functions (`compute`, `save`, `exportGeomorph`, `plotspecs`/`plotPCA`/`plotMeanShape`) are
pure R and are reused verbatim; the browser only adds trigger routes (05-02). The ONE
coupling to fix is the read source: `.build_geomorph_data` reads landmarks via
`.landmarks_for_specimen` (C `getLandmark` primary, `activeDataList[[i]][[10]]` fallback)
and curves/surfaces from `activeDataList`. For the browser path, populate those existing
`activeDataList` slots from the session model so the analytical code runs with zero edits
(RESEARCH Open Question 3, recommended default).

Purpose: DGT-03. "Identical to native" holds because it is the same code on the same input;
the seam is only where the arrays come from. Curves stay session-scoped 3-index rows
(RESEARCH Pitfall 5 / Assumption A7).
Output: `.gmw_gpa_session` / `.gmw_export_session` seams + an env builder, with the gpagen
option forwarding left untouched.
</objective>
